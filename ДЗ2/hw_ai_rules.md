## 1. Проект

**«Трекер привычек»** — веб-приложение, в котором пользователь заводит привычки, каждый день отмечает их выполнение и следит за прогрессом. Проект сквозной для всех ДЗ: в ДЗ1 выбран инструмент (Claude Code) и написано ядро расчёта серий, здесь создаются правила для агента. В ДЗ3 появятся ТЗ и макеты, в ДЗ4 — фронтенд, в ДЗ5 — бэкенд.

**Основные функции:**
- регистрация и вход;
- создание, редактирование, архивирование привычек (название, иконка, цвет, дни недели);
- отметка выполнения за сегодня (и исправление за прошедшие дни);
- текущая и рекордная серия (streak) по каждой привычке;
- статистика: процент выполнения за неделю и месяц, график по дням.

## 2. Технологический стек

| Слой | Технология | Почему |
|---|---|---|
| Язык | **TypeScript 5** (режим `strict`) | типы ловят ошибки до запуска, агенту проще понять контракт функций |
| UI | **React 18** (функциональные компоненты, хуки) | самый распространённый фреймворк, лучше всего знаком AI-моделям |
| Сборка | **Vite** | быстрый dev-сервер с hot reload |
| Стили | **Tailwind CSS 3** | стили прямо в разметке, единая дизайн-система без отдельных CSS-файлов |
| Роутинг | **React Router 6** | страницы: привычки, статистика, профиль, вход |
| Тесты | **Vitest + React Testing Library** | нативно работают с Vite |
| Бэкенд (ДЗ5) | **Supabase** (PostgreSQL, Auth, REST) | до ДЗ5 используются mock-данные |
| Качество | ESLint + Prettier | единое форматирование |

## 3. Архитектура

Структура по функциональным модулям (feature-based):

```
src/
├── app/            — корневой компонент, роутинг, провайдеры
├── pages/          — страницы (HabitsPage, StatsPage, ProfilePage, LoginPage)
├── features/
│   ├── habits/     — компоненты, хуки и логика привычек
│   └── stats/      — расчёт и отображение статистики
├── components/ui/  — переиспользуемые UI-компоненты (Button, Card, Modal…)
├── lib/            — чистые функции (даты, расчёт серий), клиент API
├── hooks/          — общие хуки
├── types/          — общие типы
└── mocks/          — mock-данные до подключения бэкенда
```

**Принципы:**
- бизнес-логика (расчёт серий, статистики) — в чистых функциях в `lib/` или `features/*/lib`, без зависимости от React. Её легко тестировать;
- компоненты отвечают только за отображение, данные получают через хуки;
- каждый компонент, загружающий данные, обрабатывает состояния loading / error / empty.

## 4. Требования к стилю кода

- **Именование:** компоненты — `PascalCase`, хуки — `useCamelCase`, функции и переменные — `camelCase`, константы — `UPPER_SNAKE_CASE`; файлы компонентов — `HabitCard.tsx`.
- **Экспорт:** только именованный (`export function HabitCard`), без `export default`.
- **Props:** интерфейс `<Компонент>Props` над компонентом.
- **Стили:** только классы Tailwind, без inline-`style`.
- **Комментарии:** на русском, объясняют «почему», а не «что»; JSDoc для экспортируемых функций.
- **Тексты интерфейса:** на русском.
- **Даты:** строки `YYYY-MM-DD`, арифметика в UTC (правило из ДЗ1 после найденного бага с переходом на зимнее время).
- **Доступность:** семантические теги, `aria-label` у кнопок-иконок, управление с клавиатуры.

## 5. Стандарты разработки

- каждая функция и компонент покрыты тестами (позитивные сценарии и ошибки);
- без `any` и `@ts-ignore`;
- новые зависимости добавляются только после согласования;
- секреты (ключи Supabase) — только через переменные окружения, `.env` в `.gitignore`;
- небольшие коммиты с понятным описанием.
