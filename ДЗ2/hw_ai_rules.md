## 1. Проект

**«ПоРовну»** — веб-приложение для дележа общих расходов в компании: поездка, общая квартира, день рождения. Участники записывают, кто за что заплатил и на кого делится расход. Приложение считает баланс каждого и предлагает минимальный набор переводов, после которого все в расчёте. Проект сквозной для всех ДЗ: в ДЗ1 выбран инструмент (Claude Code) и написано ядро расчёта долгов, здесь создаются правила для агента. В ДЗ3 появятся ТЗ и макеты, в ДЗ4 — фронтенд, в ДЗ5 — бэкенд.

**Основные функции:**
- регистрация и вход;
- группы: создание, приглашение участников по ссылке;
- расходы: кто заплатил, сумма, на кого делится (поровну или по долям), категория, дата;
- балансы участников и «кто кому должен» — минимальный список переводов;
- отметка перевода как выполненного и история операций группы.

## 2. Технологический стек

| Слой | Технология | Почему |
|---|---|---|
| Язык | **TypeScript 5** (режим `strict`) | типы ловят ошибки до запуска, агенту проще понять контракт функций |
| UI | **React 18** (функциональные компоненты, хуки) | самый распространённый фреймворк, лучше всего знаком AI-моделям |
| Сборка | **Vite** | быстрый dev-сервер с hot reload |
| Стили | **Tailwind CSS 3** | стили прямо в разметке, единая дизайн-система без отдельных CSS-файлов |
| Роутинг | **React Router 6** | страницы: группы, группа, расчёт, профиль, вход |
| Тесты | **Vitest + React Testing Library** | нативно работают с Vite |
| Бэкенд (ДЗ5) | **Supabase** (PostgreSQL, Auth, REST) | до ДЗ5 используются mock-данные |
| Качество | ESLint + Prettier | единое форматирование |

## 3. Архитектура

Структура по функциональным модулям (feature-based):

```
src/
├── app/            — корневой компонент, роутинг, провайдеры
├── pages/          — страницы (GroupsPage, GroupPage, SettleUpPage, LoginPage)
├── features/
│   ├── groups/     — группы и участники
│   ├── expenses/   — расходы: список, добавление, деление
│   └── balances/   — балансы и «кто кому должен»
├── components/ui/  — переиспользуемые UI-компоненты (Button, Card, Modal…)
├── lib/            — чистые функции (деньги, расчёт долгов), клиент API
├── hooks/          — общие хуки
├── types/          — общие типы
└── mocks/          — mock-данные до подключения бэкенда
```

**Принципы:**
- бизнес-логика (деление расходов, балансы, переводы) — в чистых функциях в `lib/` или `features/*/lib`, без зависимости от React. Её легко тестировать;
- компоненты отвечают только за отображение, данные получают через хуки;
- каждый компонент, загружающий данные, обрабатывает состояния loading / error / empty.

## 4. Требования к стилю кода

- **Именование:** компоненты — `PascalCase`, хуки — `useCamelCase`, функции и переменные — `camelCase`, константы — `UPPER_SNAKE_CASE`; файлы компонентов — `ExpenseCard.tsx`.
- **Экспорт:** только именованный (`export function ExpenseCard`), без `export default`.
- **Props:** интерфейс `<Компонент>Props` над компонентом.
- **Стили:** только классы Tailwind, без inline-`style`.
- **Комментарии:** на русском, объясняют «почему», а не «что»; JSDoc для экспортируемых функций.
- **Тексты интерфейса:** на русском.
- **Деньги:** только целые числа в копейках, отображение — через `formatRub` (правило из ДЗ1 после найденной ошибки округления во float).
- **Доступность:** семантические теги, `aria-label` у кнопок-иконок, управление с клавиатуры.

## 5. Стандарты разработки

- каждая функция и компонент покрыты тестами (позитивные сценарии и ошибки);
- без `any` и `@ts-ignore`;
- новые зависимости добавляются только после согласования;
- данные группы видят только её участники;
- секреты (ключи Supabase) — только через переменные окружения, `.env` в `.gitignore`;
- небольшие коммиты с понятным описанием.
