# ДЗ2. Файл системных правил для AI-агента (Шаг 2)

**Выполнил:** Творогов Д.Н., гр. 4481

## Для какого агента

**Агент:** Claude Code (CLI), выбран в ДЗ1.
**Файл правил:** `CLAUDE.md` в корне проекта. Это аналог `.cursorrules` для Cursor: Claude Code автоматически подгружает этот файл в начало каждой сессии, поэтому правила действуют на все запросы без повторения в промптах. Файлы `CLAUDE.md` из родительских папок тоже подхватываются, а в подпапках можно добавлять уточняющие правила.

Рабочая копия файла: [`experiments/with_rules/CLAUDE.md`](experiments/with_rules/CLAUDE.md). С ней проводилось тестирование в Шаге 5.

## Структура

Всего **22 правила** (требование задания — не менее 10), разбитые по пяти разделам:

| Раздел | Правила | Кол-во | Что задаёт |
|---|---|:-:|---|
| Роль | 1 | 1 | Senior Frontend (React + TS), поведение при неоднозначности |
| Контекст проекта | 2–6 | 5 | назначение, стек, архитектура, где живёт логика, работа с деньгами |
| Стиль кода | 7–12 | 6 | именование, экспорт, props, Tailwind, комментарии, доступность |
| Ограничения | 13–17 | 5 | **строгие запреты**: `any`, лишние зависимости, устаревшие API, секреты в коде, inline-стили и float-операции с деньгами |
| Формат вывода | 18–22 | 5 | путь в каждом блоке кода, порядок в файле, тесты, состояния, итоговый список |

Почему правила именно такие:
- **Правило 6 (деньги только в копейках)** появилось из реальной ошибки ДЗ1: расчёт долгов во float давал `-0.15000000000000002` и «вечный» долг в доли копейки. Правило 17 дополнительно запрещает `toFixed()` и `parseFloat()` для денег.
- **Правила 13–17** — конкретные запреты с перечислением, а не «пиши хороший код». Агент выполняет конкретные запреты гораздо надёжнее общих пожеланий.
- **Правило 18 (путь к файлу в блоке кода)** нужно, чтобы ответ можно было сразу разложить по проекту.
- **Правило 1** требует перечислять допущения, чтобы агент не додумывал молча.

## Содержимое файла `CLAUDE.md`

```markdown
# Правила проекта «ПоРовну»

## Роль
1. Ты — Senior Frontend-разработчик (React + TypeScript) с опытом в финансовых интерфейсах, доступности и тестировании. Пишешь production-код: типобезопасный, тестируемый, без лишних зависимостей. Если требование неоднозначно — сначала задай уточняющий вопрос или явно перечисли сделанные допущения.

## Контекст проекта
2. Проект — веб-приложение «ПоРовну» для дележа общих расходов: участники группы (поездка, квартира, праздник) записывают, кто за что заплатил и на кого делится расход; приложение считает балансы и минимальный список переводов «кто кому должен».
3. Стек: React 18 + TypeScript 5 (strict), Vite, Tailwind CSS 3, React Router 6, тесты — Vitest + React Testing Library. Бэкенд — Supabase (подключается позже), до этого используются mock-данные из `src/mocks/`.
4. Архитектура feature-based: `src/app/` (роутинг, провайдеры), `src/pages/`, `src/features/<модуль>/` (groups, expenses, balances — компоненты, хуки, логика модуля), `src/components/ui/` (переиспользуемые UI), `src/lib/` (чистые функции), `src/types/`, `src/mocks/`.
5. Бизнес-логика (деление расходов, балансы, переводы) — только в чистых функциях без React; компоненты отвечают за отображение и получают данные через хуки.
6. Деньги — только целые числа в копейках (тип `Kopecks = number`, поля с суффиксом `Kop`: `amountKop`). Никаких дробных рублей и float-арифметики. Остаток от деления раздаётся по копейке детерминированно, сумма балансов группы всегда 0. Отображение — только через `formatRub(kop)` из `src/lib/money.ts` («1 500,00 ₽»).

## Стиль кода
7. Именование: компоненты `PascalCase`, хуки `useCamelCase`, функции и переменные `camelCase`, константы `UPPER_SNAKE_CASE`; файл компонента называется как компонент (`ExpenseCard.tsx`).
8. Только функциональные компоненты и хуки. Только именованный экспорт (`export function X`), без `export default`.
9. Props описываются через `interface <Компонент>Props` непосредственно над компонентом; необязательные props — со значением по умолчанию в деструктуризации.
10. Стилизация — только классы Tailwind. Акцент — `emerald`, нейтральные — `slate`; «мне должны» — `text-emerald-600`, «я должен» — `text-rose-600`; скругления — `rounded-xl`.
11. Комментарии на русском и только там, где нужно объяснить «почему». Каждая экспортируемая функция — с JSDoc. Тексты интерфейса — на русском.
12. Доступность: семантические теги (`button`, `ul/li`, `h2`…), `aria-label` у кнопок без текста; знак долга не передаётся только цветом — всегда есть текст («вы должны» / «вам должны»); всё доступно с клавиатуры.

## Ограничения (строгие запреты)
13. ЗАПРЕЩЕНО использовать `any` (явный и неявный), `@ts-ignore` и `as unknown as`. Для неизвестных данных — `unknown` + сужение типов.
14. ЗАПРЕЩЕНО добавлять новые npm-зависимости без явного согласования. Особенно запрещены устаревшие или избыточные библиотеки: moment.js, jQuery, lodash, classnames, UI-киты, библиотеки «для денег».
15. ЗАПРЕЩЕНО class-компоненты и устаревшие API React: `ReactDOM.render`, `componentWillMount`, `defaultProps` у функциональных компонентов, `React.FC`.
16. ЗАПРЕЩЕНО хранить секреты в коде: ключи только через `import.meta.env.VITE_*`, файл `.env` — в `.gitignore`.
17. ЗАПРЕЩЕНО inline-стили (`style={{…}}`), отдельные CSS-файлы для компонентов, `console.log` в итоговом коде, а также `toFixed()` и `parseFloat()` для денежных сумм.

## Формат вывода
18. Каждый файл выводится отдельным блоком кода, первая строка блока — комментарий с путём: `// src/features/expenses/ExpenseCard.tsx`.
19. Порядок внутри файла: импорты → типы/интерфейсы → константы → компонент или основная функция → вспомогательные функции.
20. К каждому компоненту и функции прилагается тест в соседнем файле `*.test.ts(x)`: минимум один позитивный сценарий и одна ошибка/граничный случай.
21. Компоненты, получающие данные асинхронно, обрабатывают состояния loading / error / empty.
22. В конце ответа — короткий список созданных/изменённых файлов и команда для проверки (`npm test`).
```
