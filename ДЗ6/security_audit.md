### Подробности исправлений

**С-02. Open redirect через управляющие символы.** Было: проверка только начала строки — `/`, но не `//` и не `/\`. Стало: `next` отбрасывается целиком, если в нём есть символы U+0000–U+001F, U+007F, обратный слэш или он длиннее 512 символов. Добавлено 3 теста: `/\t/evil.example`, `/\n/evil.example`, `\..\` в середине пути, нулевой байт, длинный путь.

```ts
const UNSAFE_CHARS = /[\u0000-\u001f\u007f\\]/;
export function safeNext(value: string | null): string {
  if (value === null || value.length > MAX_NEXT_LENGTH || UNSAFE_CHARS.test(value)) return '/';
  return value.startsWith('/') && !value.startsWith('//') ? value : '/';
}
```

**С-03. Журнал ошибок только со своего сайта.** Браузер сам ставит заголовки `Sec-Fetch-Site` и `Origin`, и скрипт на чужой странице подделать их не может. Запрос с `Sec-Fetch-Site`, отличным от `same-origin`, или с чужим `Origin` получает 403 и в журнал не попадает: туда идёт только одна строка `client_log.cross_site`. Запросы без этих заголовков (curl) пропускаются: от целенаправленного спама защищает лимит запросов (рекомендация Р-02). 3 новых теста.

**С-04. Actions по SHA.** `actions/checkout@3d3c42e… # v7.0.1`, `actions/setup-node@949feb2… # v7.1.0`, `github/codeql-action@6f2ac81… # v4.39.0`. Комментарий с версией оставлен для людей, а Dependabot обновляет и SHA, и комментарий.

**С-05, С-06. Автоматическая проверка.** Dependabot раз в неделю проверяет npm и GitHub Actions. Мажорные версии npm он не предлагает (это отдельные миграции), обновления безопасности присылает всегда. CodeQL работает на каждый push и PR и раз в неделю. Итоги CodeQL и `npm audit` выводятся аннотациями к запуску, их видно прямо в Actions.

## 4. Принятые риски

| № | Почему не исправлено | Что снижает риск |
|---|---|---|
| С-10 `style-src 'unsafe-inline'` | Код приложения inline-стилей не использует: это запрещает правило 17 и проверяет ESLint (`JSXAttribute[name.name='style']`). Разрешение оставлено для стороннего скрипта Яндекс.Метрики, который может добавлять служебные стили; убрать его можно после проверки Метрики в браузере со строгой CSP (Р-08) | `script-src` без `unsafe-inline` и `unsafe-eval`: внедрённый CSS не может выполнить код; плюс `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'` |
| С-11 уязвимости в Tailwind CSS 3 | `npm audit fix` без смены major-версий их не устраняет, исправление есть только в Tailwind 4. Это миграция конфигурации и классов, и Dependabot-PR на неё не прошёл CI (сломалась сборка) | Пакеты работают только при сборке в CI и не попадают в сайт: `npm audit --omit=dev` = 0. Для атаки нужно подсунуть в сборку свои шаблоны путей или CSS-селекторы, а собирается только код из репозитория |
| С-12 пароль демо-аккаунтов | Учебный проект: преподавателю нужен быстрый вход без регистрации | Демо-аккаунты видят только демо-группу (RLS); данные пересоздаются командой `npm run seed:demo`; ключей и паролей служебных сервисов в документах нет |

Также осознанно оставлено: `/api/health` отдаёт короткий хеш коммита и регион. Это нужно smoke-тесту для сверки версии, секретов и данных пользователей в ответе нет.

## 6. Что сделано хорошо (подтверждено аудитом)

1. **Защита данных в базе, а не в интерфейсе.** RLS на всех 5 таблицах, права на отдельные колонки, все `security definer`-функции с `search_path = ''`, служебные функции скрыты из API (ДЗ5, миграция 5, 36 тестов БД).
2. **Заголовки безопасности.** CSP без `unsafe-inline` для скриптов, HSTS с `preload`, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`. Их наличие проверяет smoke-тест после каждой выкладки.
3. **Секреты.** В браузере и репозитории только публичный publishable-ключ Supabase. `service_role` нигде не используется, секрет Google хранится только в Supabase, `VERCEL_TOKEN` — только в Secrets GitHub и только в job выкладки. Включены secret scanning и push protection.
4. **Вход через Google с PKCE.** Одноразовый код меняется на сессию в браузере, без секрета на клиенте. Адрес возврата проходит `safeNext`.
5. **Логи без персональных данных.** На `/api/log` действует белый список полей, email, JWT и длинные токены заменяются, query из путей отрезается. В Метрику не уходят суммы, имена и токены приглашений, Вебвизор выключен.
6. **Минимальные права в CI.** `permissions: contents: read`, CodeQL получает `security-events: write` только в своём job.

## 8. Оценка

**8 из 10.** Сильные стороны — защита данных на уровне базы, строгая CSP, отсутствие секретов в клиенте и автоматическая проверка каждого изменения (форматирование, линтер, типы, 244 теста, аудит зависимостей, CodeQL, smoke-тест). Чтобы получить 9–10, нужны лимит запросов к серверным функциям (Р-02) и обновление цепочки сборки (Р-03).
