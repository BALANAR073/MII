# База данных «ПоРовну»

Сайт: **https://poravnu.vercel.app** · база: Supabase (PostgreSQL), проект `itppbtrmsbpreraaecqe`.
Схема создаётся миграциями из [`poravnu/supabase/migrations`](poravnu/supabase/migrations) (7 файлов); все они одним файлом — [`poravnu/supabase/deploy.sql`](poravnu/supabase/deploy.sql) (только для пустого проекта).

## Как связаны таблицы

```
auth.users ──1:1── profiles ──< members >── groups
                                  │            │
                                  ├──< expenses (плательщик, автор)
                                  └──< transfers (от кого, кому, автор)
```

Пользователь (`profiles`) состоит в группах через `members`. Расходы и переводы ссылаются на участника
**внутри своей группы** (составной ключ `group_id + user_id`), поэтому записать расход на постороннего нельзя.
Все суммы — целые **копейки** (`bigint`), дробных рублей в базе нет.

## Таблицы

### `auth.users` — аккаунты (служебная таблица Supabase)
Email, хеш пароля, вход через Google, дата регистрации. Приложение её напрямую не читает.
При регистрации триггер `on_auth_user_created` создаёт строку в `profiles`.

### `public.profiles` — профиль пользователя
| Колонка | Тип | Что хранит |
|---|---|---|
| `id` | uuid, PK | тот же id, что в `auth.users`; удаление аккаунта удаляет профиль |
| `email` | text | email (другие участники его **не видят** — права на колонку) |
| `name` | text, 1–40 символов | имя, которое видят в группах; меняется в «Профиле» |
| `created_at` | timestamptz | дата регистрации |

### `public.groups` — группы
| Колонка | Тип | Что хранит |
|---|---|---|
| `id` | uuid, PK | |
| `name` | text, 1–50 | название («Поездка в Казань») |
| `emoji` | text | один из 8 значков: 💸 🏙 🏠 🎂 🏕 ✈️ 🍕 🎉 |
| `owner_id` | uuid → `profiles` | владелец: может переименовать группу и сбросить ссылку |
| `invite_token` | text, уникальный | секрет ссылки-приглашения `/join/<токен>` (32 hex-символа) |
| `hidden_at` | timestamptz | группа скрыта, когда из неё вышли все |
| `created_at` | timestamptz | |

### `public.members` — кто в какой группе
| Колонка | Тип | Что хранит |
|---|---|---|
| `group_id` | uuid → `groups`, PK | |
| `user_id` | uuid, PK | id аккаунта **или** случайный id участника без аккаунта |
| `is_virtual` | boolean | `true` — участник, добавленный по имени (без аккаунта) |
| `display_name` | text | имя участника без аккаунта (у зарегистрированных — пусто, имя берётся из `profiles`) |
| `joined_at` | timestamptz | порядок вступления: кому достаётся лишняя копейка при делении |
| `left_at` | timestamptz | вышел из группы (его расходы остаются в истории) |

Когда человек открывает ссылку и выбирает «Это я — Аня», строка Ани получает его `user_id`
и `is_virtual = false`, а все её расходы и переводы переезжают вместе с ней.

### `public.expenses` — расходы
| Колонка | Тип | Что хранит |
|---|---|---|
| `id` | uuid, PK | |
| `group_id` | uuid → `groups` | |
| `title` | text, 1–60 | «Хостел», «Такси» |
| `amount_kop` | bigint, 1 … 100 000 000 | сумма в копейках (1 000 000 ₽ максимум) |
| `payer_id` | uuid → участник группы | кто заплатил |
| `split` | jsonb | на кого делим: `{"kind":"equal","memberIds":[…]}` или `{"kind":"shares","shares":[{"memberId":…,"weight":2}]}` |
| `category` | text | категория (`food`, `transport`, `housing`…); у старых расходов пусто — подбирается по названию |
| `date` | date | дата расхода |
| `created_by` | uuid → участник группы | кто записал (только он может изменить или удалить) |
| `created_at`, `updated_at` | timestamptz | |

### `public.transfers` — отмеченные переводы «я вернул долг»
| Колонка | Тип | Что хранит |
|---|---|---|
| `id` | uuid, PK | |
| `group_id` | uuid → `groups` | |
| `from_id`, `to_id` | uuid → участники группы | кто кому перевёл (разные люди) |
| `amount_kop` | bigint | сумма в копейках |
| `created_by` | uuid | кто отметил |
| `created_at` | timestamptz | |

**Балансы и «кто кому должен» в базе не хранятся** — их считает функция `group_balances` по расходам
и переводам, поэтому они не могут разойтись с историей.

## Кто что видит (Row Level Security)
- Гость не видит ни одной таблицы — только превью приглашения по токену.
- Вошедший видит только группы, где он активный участник, и их расходы, переводы и участников.
- Изменить или удалить расход может только его автор; участника без аккаунта и группу — через функции ниже.

## Серверные функции (RPC)
| Функция | Что делает |
|---|---|
| `create_group`, `update_group` | создать группу; переименовать / сменить эмодзи (владелец) |
| `get_invite_preview`, `get_invite_members` | превью приглашения и список мест «Это я — …» (доступно гостю) |
| `join_group`, `claim_member` | вступить по ссылке новым участником / занять место участника без аккаунта |
| `add_member`, `rename_member`, `remove_member` | участники без аккаунта (удалить — только при нулевом балансе) |
| `leave_group`, `rotate_invite` | выйти из группы; сбросить ссылку (владелец) |
| `my_groups`, `group_balances` | список моих групп с моим балансом; балансы участников группы |
| `delete_my_account` | удалить свой аккаунт (миграция 7) — см. ниже |

## Что сейчас лежит в базе
- **Ваш аккаунт** (вход через Google).
- **4 демо-аккаунта** `borya|anya|vika|gosha.poravnu.demo@example.com`, пароль `Demo-pass-2026` — для кнопок «Войти как…»; их группа «Поездка в Казань».
- **Мусор от сквозных тестов**: аккаунты `e2e-<код>-anya@example.com` и т. п. Скрипт `scripts/e2e-supabase.mjs` при каждом запуске регистрировал 5 новых пользователей с группой и не мог их удалить. С миграции 7 он удаляет их сам в конце прогона, а старые записи чистит запрос ниже.

### Очистка старых тестовых пользователей (Supabase → SQL Editor)
```sql
-- посмотреть
select email, created_at from auth.users where email like 'e2e-%@example.com' order by created_at;

-- удалить
begin;
delete from public.groups g using auth.users u
where g.owner_id = u.id and u.email like 'e2e-%@example.com';
delete from auth.users where email like 'e2e-%@example.com';
commit;
```

## Удаление аккаунта (миграция 7)
Кнопка «Удалить аккаунт» в профиле (у демо-аккаунтов её нет). Группы, где кроме пользователя никого нет,
удаляются целиком. В остальных его место становится участником без аккаунта с тем же именем, чтобы не
сломать чужие балансы, а владение группой переходит к участнику, вступившему раньше остальных.
