# Журнал работы с Claude Code (Шаг 5)

**Выполнил:** Творогов Д.Н., гр. 4481
**Инструмент:** Claude Code (CLI)
**Задача:** создать модуль расчёта долгов — ядро приложения «ПоРовну»: баланс каждого участника и минимальный список переводов, после которых все в расчёте — и покрыть его тестами.

Код: `test-project/src/settle.js`, тесты: `test-project/tests/settle.test.js`.

---

## Итерация 1. Генерация модуля по описанию

**Промпт:**
```
Создай в test-project ES-модуль src/settle.js для приложения «ПоРовну» (делёж общих расходов).
1) calculateBalances(expenses) — expenses: массив { payer, amount, participants },
   расход делится поровну между participants. Вернуть баланс каждого участника:
   плюс — ему должны, минус — он должен.
2) settleDebts(balances) — список переводов { from, to, amount }, после которых все в расчёте.
Напиши 3 теста на node:test в tests/settle.test.js и запусти их.
```

**Результат:** агент создал обе функции. Суммы — обычные числа в рублях, доля считается как `amount / participants.length`, переводы — попарным сопоставлением должников и кредиторов. **3 из 3 тестов прошли.**

## Итерация 2. Проверка граничных случаев

**Промпт:**
```
Добавь тесты на граничные случаи с деньгами:
- 100 ₽ на троих: сумма всех балансов должна быть ровно 0, суммы — с точностью до копейки;
- суммы с копейками: 0.10 ₽ + 0.20 ₽ на двоих — долг ровно 0.15 ₽;
- после выполнения всех переводов из settleDebts балансы всех участников равны 0.
Запусти тесты.
```

**Результат:** **3 из 6 тестов упали** (скриншот `screenshots/01_bug_before_fix.png`):
- сумма балансов «100 ₽ на троих» равна `-1.4210854715202004e-14`, а не 0;
- долг Бори `-0.15000000000000002` вместо `-0.15`;
- после всех переводов остаётся «пылинка» `-5.684341886080802e-14`.

**Проблема — деньги во float.** Числа с плавающей точкой не могут точно хранить десятичные дроби (`0.1 + 0.2 !== 0.3`), а 100 ₽ не делятся на троих без остатка (33,333…). Для приложения про деньги это критично: пользователь увидит «долг 0,00 ₽», который никогда не закроется, а проверка «все в расчёте» не сработает.

## Итерация 3. Исправление и расширение

**Промпт:**
```
Исправь: все суммы — целые числа в копейках, никаких float-рублей в расчётах.
- Остаток от деления (100 ₽ на троих) раздавай по копейке первым участникам по порядку,
  чтобы сумма балансов всегда была ровно 0.
- settleDebts: жадный алгоритм — самый крупный должник платит самому крупному кредитору;
  результат детерминирован; не больше N−1 переводов; если сумма балансов не 0 — RangeError.
- Валидация: сумма не целое число копеек → TypeError; сумма ≤ 0, пустой или
  повторяющийся список участников → RangeError.
- Добавь formatRub(kop): 150000 → «1 500,00 ₽».
Покрой всё тестами, включая поездку на 5 человек с несколькими расходами. Запусти тесты.
```

**Результат:** агент переписал модуль на целые копейки. Доля = `Math.floor(amount / n)`, остаток раздаётся по копейке: 100 ₽ на троих → 33,34 + 33,33 + 33,33. Добавлены валидация, детерминированный жадный алгоритм, `formatRub` и JSDoc. **14 из 14 тестов проходят** (скриншот `screenshots/02_tests_after_fix.png`).

Пример на данных теста «поездка на 5 человек» (4 расхода: жильё, продукты, такси, кофе):

| Перевод | Сумма |
|---|---|
| Дима → Аня | 3 493,68 ₽ |
| Гоша → Аня | 3 433,67 ₽ |
| Вика → Аня | 2 197,94 ₽ |
| Вика → Боря | 295,75 ₽ |

4 перевода на 5 человек вместо возможных 10 попарных расчётов.

> Замечание агента: жадный алгоритм гарантирует не больше N−1 переводов, но в редких случаях это не абсолютный минимум (точная минимизация — NP-трудная задача). Для компаний в 3–15 человек это приемлемо.
