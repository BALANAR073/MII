# Журнал работы с Claude Code (Шаг 5)

**Выполнил:** Творогов Д.Н.
**Инструмент:** Claude Code (CLI)
**Задача:** создать функцию расчёта серии выполнения привычки («streak») — ядро будущего трекера привычек — и покрыть её тестами.

Код: `test-project/src/streak.js`, тесты: `test-project/tests/streak.test.js`.

---

## Итерация 1. Генерация функции по описанию

**Промпт:**
```
Создай в test-project ES-модуль src/streak.js с функцией currentStreak(dates, today).
dates — массив дат выполнения привычки в формате YYYY-MM-DD, today — текущая дата.
Функция возвращает, сколько дней подряд привычка выполнялась, заканчивая сегодняшним днём.
Напиши 3 теста на node:test в tests/streak.test.js и запусти их.
```

**Результат:** агент создал функцию на основе `Date` с `setDate(d.getDate() - 1)` и три теста.

**Проблема 1 — тесты не запустились.** Скрипт `"test": "node --test tests/"` в Node.js 22 упал с ошибкой `Cannot find module '.../tests'`: Node воспринял папку как файл. Агент прочитал ошибку и заменил скрипт на `node --test tests/*.test.js`. После этого 3 из 3 тестов прошли.

## Итерация 2. Проверка граничных случаев

**Промпт:**
```
Добавь тест на серию через переход на зимнее время (2026-10-31, 2026-11-01, 2026-11-02)
и прогони все тесты в разных часовых поясах: UTC, Europe/Moscow, America/New_York, Australia/Sydney.
```

**Результат:** в UTC, Москве и Сиднее тесты прошли, а в `America/New_York` новый тест упал: **ожидалось 3, получено 2** (скриншот `screenshots/01_bug_before_fix.png`).

**Проблема 2 — баг с часовыми поясами.** `new Date('2026-11-02')` создаёт полночь по UTC, а `setDate()` вычитает день по *местному* времени. В ночь перехода на зимнее время сутки длятся 25 часов, поэтому после вычитания строка `toISOString()` «перепрыгивает» через дату и серия обрывается. Для пользователей из Москвы баг бы не проявился (в РФ нет перевода часов), но код зависел от часового пояса сервера, что недопустимо.

## Итерация 3. Исправление и расширение

**Промпт:**
```
Исправь баг: вся арифметика дат должна быть в UTC, без зависимости от часового пояса.
Также:
- если сегодня ещё не отмечено, но вчера отмечено — серия не прерывается;
- дубликаты и неотсортированный ввод не должны ломать расчёт;
- добавь longestStreak(dates) — самая длинная серия за всю историю;
- некорректный формат даты → TypeError, несуществующая дата (2026-02-30) → RangeError.
Покрой всё тестами: позитивные сценарии и ошибки. Прогони в 5 часовых поясах.
```

**Результат:** агент переписал модуль. Даты переводятся в номер дня через `Date.UTC`, поэтому арифметика стала целочисленной, без `setDate`. Добавлены `longestStreak`, валидация и JSDoc-комментарии. **12 из 12 тестов** проходят во всех пяти часовых поясах (скриншот `screenshots/02_tests_after_fix.png`).

## Итерация 4. Фиксация правил проекта

**Промпт:**
```
Создай CLAUDE.md для test-project: стек, команда запуска тестов и правила,
которые мы выработали (даты YYYY-MM-DD, арифметика только в UTC, тесты на каждую функцию).
```

**Результат:** создан `test-project/CLAUDE.md`. Claude Code автоматически подгружает его в начале каждой сессии, поэтому правило «даты только в UTC» не придётся повторять.

**Сложности и выводы:**
- Первая версия кода «выглядела правильной» и проходила простые тесты. Баг нашёлся только после явной просьбы проверить граничные случаи. Агенту нужно прямо указывать, какие крайние ситуации проверить.
- Большое преимущество CLI-агента: он сам запускает тесты, читает вывод ошибки и исправляет код. Не нужно копировать ошибки между окнами.
- Выработанные правила стоит сразу записывать в `CLAUDE.md`, чтобы не повторять их в каждом промпте. Это задел для ДЗ2.
