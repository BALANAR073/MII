## 1. Техническое задание и стек (Шаг 1)

Взято ТЗ из ДЗ3 — `ДЗ3/technical_specification.md`, версия 1.1 после AI-ревью. Реализованы все функции MVP, кроме тех, что требуют бэкенда (вход, вступление по ссылке — ДЗ5):

| Функция | Требования | Где в коде |
|---|---|---|
| Мои группы, создание группы с эмодзи | FR-2.1, FR-2.2 | `pages/GroupsPage.tsx`, `features/groups/` |
| Лента, добавление, изменение, удаление расходов | FR-3.1–3.5 | `features/expenses/` |
| Балансы, «Кто кому должен» | FR-4.1–4.6 | `features/balances/` |
| «Рассчитаться», отметка перевода (в том числе частичного) | FR-4.5, FR-5.1 | `features/transfers/TransferDialog.tsx` |

| Приглашение, выход из группы | FR-2.3, FR-2.4 | `features/groups/useGroupActions.ts` |

**Стек и UI-библиотека** — как зафиксировано в ДЗ2–ДЗ3: React + TypeScript + Vite + **Tailwind CSS**. Сторонних UI-китов нет — их запрещает правило 14. Бэкенд заменён mock-API (`src/mocks/mockApi.ts`): он повторяет будущий Supabase — задержку сети, коды ошибок и проверки прав из матрицы RLS ТЗ. Для проверки состояний есть демо-режимы `?mock=error|server|slow|empty|reset`.

## 2. Как был организован процесс

```text
ТЗ 1.1 (ДЗ3) ──► облачный агент: каркас → логика → экраны → тесты
                     │
                     ▼
        скриншоты 360–1440 px + логи консоли (Playwright, Chromium)
                     │   агент сам смотрит скриншоты и ищет баги
                     ▼
        исправления, повторные скриншоты «до / после»
                     │
                     ▼
агент на ПК (Windows): npm ci, тесты, сборка, Chrome, эмулятор iPhone SE ──► баг 10
                     │
                     ▼
агент на ПК: AI-ревью кода (claude -p, только чтение) ──► 31 находка ──► исправления, +26 тестов
```

- **Облачный агент** (Claude Code в облачной сессии) писал код и тесты, запускал `npm test`, `tsc`, `vite build` и dev-сервер. Скриншоты снимал в headless Chromium через Playwright на 6 ширинах вместе с логами консоли. Задачи в чате ставились коротко («делаем ДЗ4»), дальше агент сам разбивал работу на этапы по шаблонам из ДЗ2 и вёл список задач.
- **Агент на ПК** получал от меня готовые промпты (`prompts.md`, раздел 1). Он проверил проект на Windows, снял приложение в Chrome и в эмуляторе iPhone SE, провёл независимое AI-ревью кода.
- **Правила агента** — файл `poravnu/CLAUDE.md`: 22 правила из ДЗ2 плюс ссылка на ТЗ. Правило 10 обновлено: `text-emerald-700` вместо `emerald-600` после ревью ТЗ в ДЗ3.

## 3. Инициализация проекта (Шаг 2)

Агент создал проект без шаблонизатора, чтобы не тянуть лишнего: `package.json`, `vite.config.ts` (с настройкой Vitest и jsdom), `tsconfig.json` (strict, `noUncheckedIndexedAccess`), `tailwind.config.js`, `postcss.config.js`, `index.html` (`lang="ru"`), `.gitignore`. Зависимости поставлены через npm. Dev-сервер Vite с hot reload — `npm run dev`.

**Сложность:** в облачной среде npm сначала был закрыт. Решение — разрешил исходящий доступ к менеджерам пакетов в настройках Claude («Возможности → Разрешить исходящий доступ к сети»).

## 4. Базовая структура (Шаг 3)

Feature-based структура по правилу 4:

```text
src/app/          роутинг (App.tsx), каркас (AppLayout), сессия, общие хуки: useResource, useMutation, useMediaQuery
src/pages/        GroupsPage, GroupPage, HistoryPage, заглушки /join и 404
src/features/     balances · expenses · groups · transfers — компоненты, хуки и логика модуля
src/components/ui Button, Dialog, Toast, Skeleton, StatusMessage, Avatar, BalanceBar, roving.ts, styles.ts
src/lib/          money.ts, splitByWeights.ts, russian.ts (падежи, «на троих»), dates.ts, cx.ts
src/types/        group.ts, money.ts, api.ts (контракт API)
src/mocks/        mockApi.ts, seed.ts, demoMode.ts
```

**Роутинг** (React Router 6): `/`, `/groups/:id`, вложенные `expenses/new` и `expenses/:expenseId`, `/groups/:id/history`, `/join/:token`, `*`. Форма расхода — вложенный маршрут экрана группы: на телефоне она открывается во весь экран, на десктопе модальным окном поверх ленты, как требует ТЗ.

**Повторное использование ДЗ2:** модуль «кто кому должен» из Chain-of-Thought эксперимента (`ДЗ2/experiments/results/cot_step3.md`) перенесён почти без изменений: `splitByWeights`, `getExpenseShares`, `calculateBalances`, `suggestTransfers`. Первый же прогон дал 75 / 75 зелёных тестов, а балансы «Поездки в Казань» совпали с AC-07.1 до копейки.

- **«На троих».** Подпись «на 3 человек» звучит неестественно. Добавлена функция `splitCountText`: «на двоих», «на троих» … «на десятерых», дальше «на 11 человек».

## 6. Тестирование и отладка (Шаг 5)

### 6.1. Техники отладки с AI

1. **Мультимодальный анализ скриншотов.** Агент снимал экраны в Chromium на ширинах 360–1440 px, сам рассматривал изображения и формулировал баги: что видно, где причина в коде, как исправить. Затем пересъёмка «после».
2. **Интерпретация логов консоли.** Скрипт съёмки собирает `console.*` и `pageerror` и проверяет `scrollWidth ≤ innerWidth` (горизонтальная прокрутка).
3. **Генерация исправлений** — по каждому багу; после правки — `tsc` и все тесты.
4. **Проверка вторым агентом на другой ОС.** Агент на Windows нашёл баг, невидимый в Linux.
5. **Автоматическая проверка доступности** axe-core: нашла ошибку ARIA, которую не видно ни на скриншоте, ни в тестах.

**Проблемы в самих тестах и инструментах (тоже найдены и решены):**
- **Нестабильный тест** оптимистичного добавления падал примерно 1 раз из 6. При задержке mock-API 30 мс строка «Сохраняется…» иногда исчезала раньше проверки. Задержка в тесте увеличена до 300 мс, после этого 0 падений из 10.
- **Невидимые символы.** При записи файлов агентом escape-последовательности ` ` превратились в настоящие неразрывные пробелы — код работал, но читать его было нельзя. Агент нашёл их скриптом и вернул явные ` ` и `−`.
- **Нормализация текста в Testing Library.** Неразрывный пробел в поиске по тексту сводится к обычному. В ожиданиях тестов используется обычный пробел, с комментарием.

## 8. Оптимизация и рефакторинг (Шаг 7)

**Рефакторинг, сделанный агентом:**
- `GroupPage.tsx` (340 строк) разбит на хуки `useOptimisticExpenses`, `useDeferredDelete`, `useGroupActions` и компоненты `BalancesPanel`, `GroupTabs`.
- Повторявшийся в 10 файлах набор классов фокуса вынесен в `components/ui/styles.ts`.
- Контракт API (`ApiError`, `ExpenseInput`) и текущий пользователь вынесены из `mocks/` в `types/api.ts` и `app/session.ts`. В ДЗ5 замена mock на Supabase затронет только реализацию API.

**Производительность:**
- Расчёт балансов мемоизирован (`useSettlement`). Замер: 50 участников и 1000 расходов — **≈8 мс** при требовании NFR-7 в 50 мс, тест закреплён.
- Боковая панель групп больше не монтируется на телефоне — минус лишний сетевой запрос.
- Ответы устаревших запросов отбрасываются (`useResource`), двойное нажатие на кнопки блокируется (`useMutation`).
- Сборка: 232 КБ JS (73 КБ gzip), 21 КБ CSS (5 КБ gzip).

**AI-ревью кода.** Независимый агент на ПК с запретом на правку файлов проверил код по правилам проекта и ТЗ: 31 находка, оценка **7 / 10**. Исправлено 22 полностью и 6 частично, 2 закрыты уточнением ТЗ, 1 отклонена с обоснованием. Самые ценные находки:
- отмена удаления не работала при уходе со страницы;
- сбой сети при фоновом обновлении ронял весь экран;
- не хватало клавиатурной навигации по вкладкам и радиокнопкам.

Добавлено 26 тестов. Подробно — `ai_code_review_response.md`.

## 9. Какие техники оказались наиболее эффективными

| Техника | Эффект |
|---|---|
| **Повторное использование кода из CoT (ДЗ2)** | ядро расчётов заработало с первого запуска: 75 / 75 тестов |
| **Правила агента (`CLAUDE.md`)** | ревьюер не нашёл ни одного нарушения запретов (`any`, `console.log`, `toFixed`, inline-стили) |
| **Скриншоты на нескольких ширинах + анализ изображения агентом** | 7 из 11 багов найдены именно так; цикл «снять → увидеть → исправить → переснять» занимает минуты |
| **Проверка вторым агентом на другой ОС** | нашёл баг, невидимый в Linux, сам поставил диагноз и предложил минимальную правку |
| **AI-ревью кода с запретом на изменения** | нашло ошибки асинхронной логики, которые не видны на скриншотах и не ловятся «счастливыми» тестами |
| **Автоматическая проверка axe** | сразу нашла нарушение ARIA |
| **Названия тестов по критериям приёмки ДЗ3** | видно, какое требование проверено и какое ещё нет |

Наименее эффективно — просить агента «сделать красиво» без конкретики. Работают промпты с конкретной шириной, скриншотом, текстом ошибки и ожидаемым результатом: см. `prompts.md`, разделы 2–4.

## 10. Выводы и рекомендации

1. **Все 8 шагов выполнены.** Приложение реализует 5 функций MVP из ТЗ, запускается локально на Linux и Windows, корректно отображается на ширинах от 360 до 1440 px. 141 автотест проходит.
2. **Агент пишет рабочий код быстро, но «зелёные» тесты и чистые скриншоты — не гарантия.** Половина серьёзных проблем нашлась только с другой точки зрения: другая ОС, независимый ревьюер, автоматическая проверка доступности. Рекомендация — всегда добавлять хотя бы одну такую проверку.
3. **Отлаживать по скриншотам эффективно, если снимать систематически:** фиксированный набор ширин, режимы ошибок, лог консоли и проверка горизонтальной прокрутки в одном скрипте. Тогда агент находит баги вёрстки сам, без описания человеком.
4. **Решения о требованиях должен принимать человек.** Агент предлагал несколько изменений, противоречащих другим требованиям: «Повторить» при идущем запросе, формулировки с родом, Error Boundary вопреки правилу 15. Такие решения записаны в ТЗ, чтобы следующий агент не додумывал их сам.
5. **Для ДЗ5:** заменить mock-API реализацией на Supabase за тем же контрактом (`types/api.ts`), добавить вход и вступление по ссылке, перенести отправку удаления при закрытии вкладки на `keepalive` или `sendBeacon` (находка 3).
