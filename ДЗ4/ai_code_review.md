## 3) С чего начать

1. **Перестроить отложенное удаление (п. 1, 3, 4, 25, 28).** Очередь удалений вынести на уровень приложения рядом с `ToastProvider`. Отмена должна работать, пока жив тост, независимо от маршрута. Для закрытия вкладки — `sendBeacon`/`keepalive` по FR-3.5. Всё это закрыть тестом на фейковых таймерах. Сейчас пользователь может нажать «Отменить» и всё равно потерять расход — для финансового приложения это худший сценарий.
2. **Не ронять экран при фоновых ошибках (п. 2, 7).** Тихая перезагрузка не должна заменять данные экраном ошибки. Расчёты, которые бросают исключения, нужно накрыть Error Boundary (по согласованию с правилами 14/15). Сейчас сбой сети при возврате на вкладку уничтожает оптимистичные строки и досрочно запускает удаления.
3. **Фокус и клавиатура (п. 8, 9, 10) + `vitest-axe` (п. 29).** Управлять фокусом при смене режима диалога и после удаления, поставить тост на паузу при фокусе, реализовать стрелки для tabs/radio. Затем подключить axe-проверку, которую ТЗ уже записало в критерии приёмки.

## 4) Итоговая оценка: **7 / 10**

Сильная основа: денежная арифметика и алгоритмы балансов на уровне production, типизация строгая и без обходов, формальные запреты правил не нарушены, структура в целом feature-based. Оценку снижают три вещи. Асинхронные сценарии, которые ТЗ выделяет особо (отложенное удаление, фоновое обновление, откат оптимистичного добавления), работают только на «счастливом пути» и ломаются при навигации или сбое сети. Есть заметные пробелы в клавиатурной доступности. Тесты хорошо покрывают чистую логику, но почти не покрывают хуки, UI-примитивы и проверки из критериев приёмки (axe, таймеры удаления, «История»).
