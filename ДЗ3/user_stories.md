# ДЗ3. User Story Mapping «ПоРовну» (Шаги 3–5)

**Выполнил:** Творогов Д.Н., гр. 4481

## 1. Пользовательские роли (Personas)

| Persona | Кто это | Цель | Боль |
|---|---|---|---|
| **Аня — организатор** | 21 год, студентка, бронирует жильё и платит крупные суммы за всех | быстро вернуть свои деньги, не напоминая каждому лично | ведёт таблицу в заметках, путается в 20 расходах |
| **Боря — участник** | 20 лет, платит за мелочи, переводы делает через СБП | точно знать, сколько и кому перевести, без споров | не хочет переплачивать и разбираться в таблицах |
| **Вика — сосед по квартире** | 22 года, живёт в квартире с тремя соседями | ежемесячно делить аренду и коммуналку без ссор | одни и те же расчёты каждый месяц |

Технические роли: **участник группы** (все действия с расходами группы), **создатель группы** (дополнительно перевыпуск ссылки-приглашения), **гость** (только вход и регистрация).

## 2. Пользовательские сценарии (User Journeys)

### «Счастливый путь» 1. Поездка (Аня)
1. Аня регистрируется → создаёт группу «Поездка в Казань 🏙» → копирует ссылку-приглашение в чат.
2. Друзья открывают ссылку → входят → попадают в группу.
3. Во время поездки каждый добавляет свои расходы: «Хостел 12 000 ₽, на всех».
4. В конце Аня открывает вкладку «Балансы» и видит: ей должны 8 135,80 ₽, и это 3 перевода.
5. Боря видит «Вы должны Ане 940,75 ₽» → переводит по СБП → нажимает «Отметить перевод».
6. Балансы пересчитываются, и когда все переводы отмечены, у всех «в расчёте».

### «Счастливый путь» 2. Общая квартира (Вика)
1. Вика создаёт группу «Квартира на Баумана» и приглашает соседей.
2. Каждый месяц добавляет «Аренда 40 000 ₽, на всех» и «Интернет 600 ₽».
3. Сосед, который не пользуется стиралкой, исключается из расхода «Порошок».
4. Раз в месяц все смотрят «Кто кому должен» и рассчитываются.

### Нормальные сценарии
- исправить сумму в расходе, внесённом с опечаткой;
- разделить кофе по долям: «мне два, тебе один»;
- открыть историю и посмотреть, кто и когда отметил перевод;
- выйти из группы после поездки.

## 4. User Stories и критерии приёмки (Шаг 4)

Формат историй — «Как [роль], я хочу [действие], чтобы [результат]». Критерии приёмки — «Given [условие] When [действие] Then [результат]». Все суммы в критериях указаны в рублях, хранятся в копейках.

### Must have

#### US-01. Регистрация и вход
**Как** новый пользователь, **я хочу** зарегистрироваться по email и паролю, **чтобы** мои группы были доступны только мне и с любого устройства.
- **AC-01.1** Given гость на экране регистрации, When вводит корректные email, имя и пароль от 8 символов и нажимает «Создать аккаунт», Then аккаунт создаётся и открывается список групп.
- **AC-01.2** Given email уже зарегистрирован, When гость пытается зарегистрироваться с ним, Then показывается «Этот email уже зарегистрирован. Войти?», а введённые данные не сбрасываются.
- **AC-01.3** Given неверный пароль, When пользователь нажимает «Войти», Then показывается «Неверный email или пароль» (без уточнения, что именно неверно).

#### US-02. Создать группу
**Как** организатор, **я хочу** создать группу с названием, **чтобы** собрать в ней все расходы поездки.
- **AC-02.1** Given пользователь на списке групп, When вводит название «Поездка в Казань» и нажимает «Создать», Then группа появляется в списке, а он сам становится её участником и создателем.
- **AC-02.2** Given пустое название или название длиннее 50 символов, When пользователь нажимает «Создать», Then группа не создаётся, под полем показывается подсказка «Введите название» (или «Не длиннее 50 символов»), фокус остаётся в поле.

#### US-03. Пригласить по ссылке
**Как** организатор, **я хочу** отправить друзьям ссылку-приглашение, **чтобы** они вступили в группу без ручного добавления.
- **AC-03.1** Given участник группы, When нажимает «Пригласить», Then ссылка копируется в буфер и показывается «Ссылка скопирована».
- **AC-03.2** Given вошедший пользователь открывает ссылку, When нажимает «Вступить», Then он становится участником, а группа открывается.
- **AC-03.3** Given гость открывает ссылку, When входит или регистрируется, Then после входа автоматически вступает в группу.
- **AC-03.4** Given ссылка недействительна, When пользователь её открывает, Then показывается «Приглашение недействительно — попросите новую ссылку».

#### US-04. Добавить расход поровну
**Как** участник, **я хочу** быстро записать, что я заплатил и на кого делится трата, **чтобы** не держать расходы в голове.
- **AC-04.1** Given форма расхода (по умолчанию: платил — я, делится — на всех), When пользователь вводит «Хостел» и «12000» и нажимает «Сохранить», Then расход появляется сверху ленты, а балансы пересчитываются.
- **AC-04.2** Given сумма 1 000 ₽ на троих, When расход сохранён, Then доли равны 333,34 / 333,33 / 333,33 ₽, а их сумма ровно 1 000,00 ₽.
- **AC-04.3** Given сумма 0, отрицательная или с тремя знаками после запятой, When пользователь нажимает «Сохранить», Then показывается «Введите сумму больше 0, до копеек», а расход не сохраняется.
- **AC-04.4** Given не выбран ни один участник деления, When пользователь нажимает «Сохранить», Then показывается «Выберите хотя бы одного участника».

#### US-06. Балансы участников
**Как** участник, **я хочу** видеть свой баланс и балансы остальных, **чтобы** понимать, сколько должен я и сколько должны мне.
- **AC-06.1** Given расходы группы, When пользователь открывает вкладку «Балансы», Then у каждого участника показан баланс с текстом «вам должны» / «должен» / «в расчёте» и цветом (зелёный / красный / серый).
- **AC-06.2** Given любые расходы и переводы, When балансы рассчитаны, Then сумма всех балансов равна 0,00 ₽.
- **AC-06.3** Given в группе ещё нет расходов, When пользователь открывает «Балансы», Then показывается «Пока все в расчёте. Добавьте первый расход» с кнопкой «Добавить расход».

#### US-07. Кто кому должен
**Как** участник, **я хочу** видеть минимальный список переводов, **чтобы** рассчитаться за несколько переводов, а не «каждый с каждым».
- **AC-07.1** Given балансы Аня +8 135,80, Боря −940,75, Вика −3 197,53, Гоша −3 997,52 ₽, When открыт блок «Кто кому должен», Then показаны 3 перевода: Гоша → Аня 3 997,52; Вика → Аня 3 197,53; Боря → Аня 940,75 ₽.
- **AC-07.2** Given N участников с ненулевым балансом, When рассчитан список, Then переводов не больше N−1, и после их выполнения все балансы равны 0.
- **AC-07.3** Given все в расчёте, When открыт блок, Then показывается «Все в расчёте 🎉» без списка.

#### US-08. Отметить перевод
**Как** участник перевода (должник или получатель), **я хочу** отметить, что деньги переведены, **чтобы** долг исчез из списка и это увидели все.
- **AC-08.1** Given перевод «Боря → Аня 940,75 ₽», When Боря нажимает «Отметить перевод» и подтверждает, Then перевод попадает в историю, баланс Бори становится 0, а у Ани уменьшается на 940,75 ₽.
- **AC-08.2** Given пользователь не участвует в переводе, When смотрит на него, Then кнопки «Отметить перевод» у него нет.
- **AC-08.3** Given нет сети при отметке, When пользователь нажимает «Отметить перевод», Then показывается «Не удалось сохранить. Проверьте интернет» с кнопкой «Повторить», а балансы не меняются.

### Should have

#### US-05. Деление по долям
**Как** участник, **я хочу** разделить расход не поровну, а по долям (2:1), **чтобы** каждый платил за то, что потребил.
- **AC-05.1** Given расход 600 ₽ с долями Гоша 2 и Боря 1, When расход сохранён, Then доли равны 400,00 и 200,00 ₽.
- **AC-05.2** Given расход 100 ₽ с долями 1:1:1, When расход сохранён, Then доли 33,34 / 33,33 / 33,33 ₽, сумма ровно 100,00 ₽.
- **AC-05.3** Given доля 0, отрицательная или дробная, When пользователь сохраняет расход, Then показывается «Доля — целое число от 1 до 1000».

#### US-09. Редактировать и удалить расход
**Как** автор расхода, **я хочу** исправить или удалить его, **чтобы** исправить опечатку.
- **AC-09.1** Given свой расход, When пользователь меняет сумму и сохраняет, Then расход и балансы обновляются.
- **AC-09.2** Given свой расход, When пользователь нажимает «Удалить» и подтверждает, Then расход исчезает, балансы пересчитываются, и 5 секунд доступна кнопка «Отменить».
- **AC-09.3** Given чужой расход, When пользователь открывает его, Then кнопки «Изменить» и «Удалить» скрыты, расход открывается только для просмотра.

#### US-10. История операций
**Как** участник, **я хочу** видеть историю расходов и переводов, **чтобы** проверить, откуда взялся мой долг.
- **AC-10.1** Given группа с расходами и переводами, When пользователь открывает «История», Then записи показаны по дате от новых к старым, с автором и суммой.

#### US-11. Выйти из группы
**Как** участник, **я хочу** выйти из группы после поездки, **чтобы** она не мешала в списке.
- **AC-11.1** Given баланс пользователя 0, When он нажимает «Выйти из группы» и подтверждает, Then группа пропадает из его списка, а в истории он отображается с пометкой «вышел из группы».
- **AC-11.2** Given баланс не 0, When пользователь нажимает «Выйти», Then показывается «Сначала рассчитайтесь: вы должны 940,75 ₽», и выход не выполняется.

### Nice to have (без подробных критериев на этапе MVP)
- **US-12.** Как организатор, я хочу выбрать цвет группы и любой эмодзи (в MVP — только 8 готовых), чтобы быстрее находить группу в списке.
- **US-13.** Как участник, я хочу указывать категорию расхода, чтобы видеть, на что ушли деньги.
- **US-14.** Как участник, я хочу фильтровать расходы по плательщику, чтобы проверить свои траты.
- **US-15.** Как организатор, я хочу отправить вежливое напоминание о долге, чтобы не писать его самому.

## 5. Негативные сценарии и обработка ошибок (Шаг 5)

| Тип | Ситуация | UX-решение |
|---|---|---|
| **Валидация** | сумма 0, отрицательная, больше 1 000 000 ₽, больше 2 знаков после запятой | ошибка под полем при потере фокуса и при нажатии «Сохранить» (кнопка всегда активна, запрос не отправляется, фокус — на первое ошибочное поле), введённые данные не теряются |
| | пустое название группы или расхода | подсказка «Введите название», фокус на поле |
| | не выбран ни один участник деления | ошибка под списком участников |
| | доли не целые или 0 | «Доля — целое число от 1 до 1000» |
| **Нет данных** | у пользователя нет групп | иллюстрация + «Создайте первую группу или попросите ссылку у друзей» + кнопка «Создать группу» |
| | в группе нет расходов | «Пока все в расчёте. Добавьте первый расход» + кнопка |
| | все в расчёте | «Все в расчёте 🎉» вместо списка переводов |
| **Сеть** | загрузка группы не удалась | скелетон при загрузке; при ошибке — «Не удалось загрузить группу» + «Повторить» |
| | сохранение расхода не удалось | форма не закрывается, данные сохраняются, тост «Не удалось сохранить. Проверьте интернет» + «Повторить» |
| | ошибка сервера 500 | «Что-то пошло не так. Мы уже разбираемся» + «Повторить», детали — в консоль разработчика |
| | долгий ответ (> 10 с) | индикатор на кнопке, кнопка заблокирована от повторного нажатия, через 10 с — предложение повторить |
| **Доступ** | сессия истекла (401) | переход на вход с сообщением «Сессия истекла, войдите снова», после входа — возврат на ту же страницу |
| | чужая группа или удалённая группа (403/404) | «Группа недоступна — возможно, вы вышли из неё или ссылка устарела» + «К моим группам» |
| | редактирование чужого расхода | кнопки скрыты; при попытке через API — 403 и тост «Изменять можно только свои расходы» |
| **Конфликты** | расход удалили (с другого устройства автора), пока его редактировали | «Этот расход уже удалён» + обновление ленты |
| | выход из группы с ненулевым балансом | запрет с суммой долга (AC-11.2) |

## 6. Как использовался AI-агент

Истории, критерии приёмки и список негативных сценариев сгенерированы Claude Code на основе `project_description.md` по промпту:

```text
Role: ты — продуктовый аналитик.
Task: по описанию проекта «ПоРовну» (@project_description.md) составь User Story Mapping:
personas, «счастливые пути» и нормальные сценарии, карту историй по активностям,
истории в формате «Как [роль], я хочу [действие], чтобы [результат]» с приоритетом
Must / Should / Nice, для каждой истории Must и Should — критерии приёмки Given-When-Then,
включая негативные. Отдельно — таблица негативных сценариев (валидация, нет данных,
сеть, неавторизованный доступ) с UX-решениями.
Context: деньги в копейках, остаток при делении раздаётся по копейке, переводы — не больше N−1.
Format: Markdown, суммы в примерах — реальные расчёты по данным UI-концепций.
```

Числа в критериях (AC-04.2, AC-05.1, AC-05.2, AC-07.1) проверены расчётом модулем `settle.js` из ДЗ1.
