# Техническое задание: веб-приложение «ПоРовну» (MVP)

**Выполнил:** Творогов Д.Н., гр. 4481 · **Версия:** 1.0 · **Связанные документы:** `project_description.md`, `user_stories.md`, `ui_concepts/ui_description.md`, правила агента — `../ДЗ2/rules.md`

> Документ написан для AI-инженера (Claude Code). Каждое требование имеет идентификатор (FR, NFR, ERR) и ссылку на user story (US) и критерии приёмки (AC), чтобы на него можно было сослаться в промпте: «реализуй FR-3.2, критерии AC-04.1–AC-04.4».

## 1. Описание проекта

**«ПоРовну»** — адаптивное веб-приложение для дележа общих расходов в компании. Участники группы записывают, кто за что заплатил и на кого делится расход; приложение показывает балансы и минимальный список переводов, после которого все в расчёте.

**Стек:** React 18 + TypeScript 5 (strict), Vite, Tailwind CSS 3, React Router 6; тесты — Vitest + React Testing Library; бэкенд — Supabase (PostgreSQL, Auth, REST, RLS). До подключения бэкенда (ДЗ5) — mock-данные из `src/mocks/`.

**Экраны:**

| Маршрут | Экран | Истории |
|---|---|---|
| `/login`, `/register` | Вход, регистрация | US-01 |
| `/` | Мои группы | US-02 |
| `/join/:token` | Вступление по приглашению | US-03 |
| `/groups/:id` | Группа: вкладки «Расходы» и «Балансы» | US-04, 06, 07, 08 |
| `/groups/:id/expenses/new`, `/groups/:id/expenses/:expenseId` | Форма расхода (на мобильном — полноэкранная, на десктопе — модальное окно) | US-04, 05, 09 |
| `/groups/:id/history` | История операций | US-10 |

## 2. Целевая аудитория

Студенты и молодёжь 18–30 лет, компании друзей в поездках (3–10 человек, 10–50 расходов), соседи по квартире, организаторы праздников. Основное устройство — смартфон (**mobile-first**, от 360 px), вторичное — десктоп. Подробнее — `project_description.md`, раздел 3.

## 3. Модель данных

Все суммы — `amountKop: number`, целые копейки (`Kopecks`). Идентификаторы — UUID.

| Сущность | Поля |
|---|---|
| `Profile` | `id`, `email`, `name` (1–40 символов), `createdAt` |
| `Group` | `id`, `name` (1–50), `emoji`, `ownerId`, `inviteToken`, `createdAt` |
| `Member` | `groupId`, `userId`, `joinedAt`, `leftAt: string \| null` (мягкое удаление) |
| `Expense` | `id`, `groupId`, `title` (1–60), `amountKop` (1…100 000 000), `payerId`, `split`, `category?`, `date`, `createdBy`, `createdAt`, `updatedAt` |
| `ExpenseSplit` | `{ kind: 'equal', memberIds: string[] }` \| `{ kind: 'shares', shares: { memberId, weight: 1…1000 }[] }` |
| `Transfer` | `id`, `groupId`, `fromId`, `toId`, `amountKop`, `createdBy`, `createdAt` |

**Инварианты:** сумма долей расхода = `amountKop`; сумма балансов группы = 0; `fromId ≠ toId`.

## 4. Функциональные требования

### F-1. Аутентификация (US-01)
- **FR-1.1** Регистрация по email, имени и паролю (не короче 8 символов); вход по email и паролю; выход.
- **FR-1.2** Все маршруты, кроме `/login`, `/register`, `/join/:token`, требуют входа; неавторизованный пользователь перенаправляется на `/login` с сохранением исходного адреса.
- **FR-1.3** Ошибка входа не раскрывает, что именно неверно (AC-01.3).

### F-2. Группы и участники (US-02, 03, 11)
- **FR-2.1** Список групп пользователя: название, эмодзи, число участников, баланс пользователя в группе.
- **FR-2.2** Создание группы (название 1–50 символов); создатель становится участником.
- **FR-2.3** Приглашение: кнопка «Пригласить» копирует ссылку `/join/:inviteToken`; переход по ссылке → вступление (AC-03.2, 03.3); неверный токен → AC-03.4.
- **FR-2.4** Выход из группы только при нулевом балансе (AC-11.1, 11.2); вышедший остаётся в истории с пометкой «вышел из группы» и не доступен для выбора в новых расходах.

### F-3. Расходы (US-04, 05, 09)
- **FR-3.1** Лента расходов группы от новых к старым: название, сумма, плательщик, на сколько человек делится, «ваша доля».
- **FR-3.2** Форма расхода: название, сумма, плательщик (по умолчанию — текущий пользователь), участники деления (по умолчанию — все активные), режим «поровну» / «по долям», дата (по умолчанию — сегодня).
- **FR-3.3** Ввод суммы в рублях с запятой или точкой, не более 2 знаков после запятой; преобразование в копейки без float (разбор строки).
- **FR-3.4** Деление: функция `splitByWeights(amountKop, weights)` — база `floor(amount × w / Σw)`, остаток раздаётся по копейке методом наибольших остатков, при равенстве — по порядку участника в группе (AC-04.2, 05.1, 05.2).
- **FR-3.5** Редактировать и удалять расход может только его автор; удаление с подтверждением и отменой в течение 5 секунд (AC-09.1–09.3).

### F-4. Балансы и «Кто кому должен» (US-06, 07)
- **FR-4.1** Баланс участника = Σ оплаченного − Σ своих долей + Σ отправленных переводов − Σ полученных переводов.
- **FR-4.2** Отображение: «вам должны X» (`text-emerald-600`), «должен X» (`text-rose-600`), «в расчёте» (`text-slate-500`); знак долга всегда передан текстом, не только цветом.
- **FR-4.3** Список переводов — детерминированный жадный алгоритм (крупнейший должник → крупнейшему кредитору, сначала закрываются точно совпадающие пары); не больше N−1 переводов (AC-07.1, 07.2).
- **FR-4.4** Расчёт — чистые функции в `src/features/balances/` (за основу — модуль из ДЗ2, `experiments/results/cot_step3.md`, `cot_step4.md`).

### F-5. Переводы и история (US-08, 10)
- **FR-5.1** Кнопка «Отметить перевод» доступна только отправителю и получателю перевода; после подтверждения создаётся `Transfer`, балансы пересчитываются (AC-08.1, 08.2).
- **FR-5.2** История: расходы и переводы одной лентой по дате, с автором и суммой.

## 5. Нефункциональные требования

| ID | Функция | Требование |
|---|---|---|
| NFR-1 | все | Адаптивность: 360–1440 px; мобильная раскладка — одна колонка, нижняя кнопка «+»; десктоп — лента и панель балансов рядом. Без горизонтальной прокрутки |
| NFR-2 | все | Доступность: семантические теги, фокус виден, всё доступно с клавиатуры, контраст текста не ниже 4.5:1, `aria-label` у кнопок-иконок |

| NFR-4 | F-1, F-2 | Безопасность: данные группы доступны только её участникам (RLS в Supabase); пароли хранит Supabase Auth; ключи — только в `.env` |
| NFR-5 | F-3, F-4 | Точность: все расчёты в целых копейках; запрещены float-арифметика, `toFixed`, `parseFloat` для денег; сумма балансов = 0 проверяется тестами |
| NFR-6 | F-3 | Скорость: добавление расхода — не более 3 обязательных полей и 15 секунд; оптимистичное обновление ленты |
| NFR-7 | F-4 | Производительность: расчёт балансов для 50 участников и 1 000 расходов — менее 50 мс в браузере |
| NFR-8 | все | Качество: TypeScript strict без `any`; тесты Vitest на каждую функцию расчёта (позитивные и граничные) и на ключевые компоненты; правила кода — `ДЗ2/rules.md` |
| NFR-9 | все | Состояния loading (скелетон), error (сообщение + «Повторить»), empty (пояснение + действие) у каждого экрана с загрузкой данных |

## 6. Обработка ошибок

| ID | Ошибка | Где | Поведение |
|---|---|---|---|
| ERR-1 | Невалидная сумма, название, доли, пустой список участников | форма расхода, группы | ошибка под полем, кнопка неактивна, данные не теряются (AC-04.3, 04.4, 05.3, 02.2) |
| ERR-2 | Нет групп / нет расходов / все в расчёте | списки | empty-состояние с пояснением и действием (AC-06.3, 07.3) |
| ERR-3 | Сетевая ошибка при загрузке | экраны | скелетон → «Не удалось загрузить…» + «Повторить» |
| ERR-4 | Сетевая ошибка при сохранении | формы, «Отметить перевод» | форма не закрывается, тост с «Повторить», балансы не меняются (AC-08.3) |
| ERR-5 | 500 и неожиданные ошибки | все | «Что-то пошло не так» + «Повторить»; технические детали — только в консоль разработчика |
| ERR-6 | 401 — сессия истекла | все | переход на `/login` с сообщением, после входа — возврат на исходный адрес |
| ERR-7 | 403/404 — нет доступа к группе или расходу | группа, расход | «Группа недоступна…» + «К моим группам»; для чужого расхода — кнопки скрыты, при прямом запросе — тост |
| ERR-8 | Недействительное приглашение | `/join/:token` | AC-03.4 |
| ERR-9 | Выход с ненулевым балансом | группа | запрет с суммой долга (AC-11.2) |
| ERR-10 | Конфликт: расход удалён другим участником | форма расхода | «Этот расход уже удалён» + обновление ленты |

## 7. Критерии готовности MVP

- реализованы все истории Must have (US-01–04, 06–08) и выполнены их критерии приёмки;
- автотесты проходят, включая инварианты: сумма долей = сумма расхода, сумма балансов = 0, после переводов все балансы = 0;
- интерфейс проверен на 360, 768 и 1280 px;
- нет ошибок TypeScript и предупреждений линтера.
