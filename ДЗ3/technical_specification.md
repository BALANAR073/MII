## 1. Описание проекта

**«ПоРовну»** — адаптивное веб-приложение для дележа общих расходов в компании. Участники группы записывают, кто за что заплатил и на кого делится расход; приложение показывает балансы и минимальный список переводов, после которого все в расчёте.

**Стек:** React 18 + TypeScript 5 (strict), Vite, Tailwind CSS 3, React Router 6; тесты — Vitest + React Testing Library; бэкенд — Supabase (PostgreSQL, Auth, REST, RLS). До подключения бэкенда (ДЗ5) — mock-данные из `src/mocks/`.

**Экраны:**

| Маршрут | Экран | Истории |
|---|---|---|
| `/login`, `/register` | Вход, регистрация | US-01 |
| `/` | Мои группы | US-02 |
| `/join/:token` | Вступление по приглашению | US-03 |
| `/groups/:id` | Группа: шапка с балансом, вкладки «Расходы» и «Балансы» | US-04, 06, 07, 08 |
| `/groups/:id/expenses/new`, `/groups/:id/expenses/:expenseId` | Форма расхода (на мобильном — полноэкранная, на десктопе — модальное окно); для чужого расхода — режим просмотра | US-04, 05, 09 |
| `/groups/:id/history` | История операций | US-10 |

### 1.1. Вне рамок MVP

Не реализуются, даже если кажутся логичными: цвет группы (US-12), категории расходов (US-13, поле `category` зарезервировано), фильтр по плательщику (US-14), напоминания о долге (US-15), несколько валют, переименование и удаление группы, исключение участника другим участником, сброс пароля, подтверждение email, обновление в реальном времени (Supabase Realtime), загрузка чеков.

### 1.2. Решения по открытым вопросам

Приняты по итогам AI-ревью (раздел 4 `tz_ai_review.md`):

| № | Вопрос | Решение |
|---|---|---|
| Q1 | Порядок раздачи лишних копеек | Порядок участника в группе: `joinedAt` по возрастанию, при равенстве — `userId` по возрастанию. Плательщик приоритета не имеет |
| Q2 | Частичный перевод, отмена перевода | Сумма перевода редактируется (по умолчанию — из подсказки, допустимо от 0,01 ₽ до суммы подсказки). Ошибочный перевод может удалить его автор |
| Q3 | Что делает «Рассчитаться» | Если у пользователя один предложенный перевод — открывает диалог «Отметить перевод» с этим переводом; если несколько — открывает вкладку «Балансы» и подсвечивает его строки. Кнопка видна только тому, кто должен |
| Q4 | Выход создателя | Разрешён при нулевом балансе; `ownerId` переходит к участнику с самым ранним `joinedAt`. Последний вышедший участник — группа скрывается у всех |
| Q5 | Возврат и вышедшие участники | Вышедший может вернуться по действующей ссылке (`leftAt` обнуляется). Расход, в котором участвует вышедший, нельзя изменить или удалить |
| Q6 | Срок ссылки-приглашения | Бессрочная; создатель может её перевыпустить, старая ссылка становится недействительной |
| Q7 | Подтверждение email, сброс пароля | Подтверждение email в Supabase отключено (вход сразу после регистрации); сброс пароля — вне MVP |
| Q8 | Реальное время | Нет. Данные обновляются при открытии экрана, при возврате фокуса на вкладку браузера и по «Повторить» |
| Q9 | Лимит участников | 50 человек в группе |
| Q10 | Эмодзи, переименование | Эмодзи выбирается при создании из 8 вариантов (по умолчанию 💸); переименование — вне MVP |
| Q11 | Расход без плательщика среди участников | Разрешён (например, подарок) |
| Q12 | Сортировка ленты и истории | По `date` от новых к старым, при равенстве — по `createdAt` от новых к старым |

## 2. Целевая аудитория

Студенты и молодёжь 18–30 лет, компании друзей в поездках (3–10 человек, 10–50 расходов), соседи по квартире, организаторы праздников. Основное устройство — смартфон (**mobile-first**, от 360 px), вторичное — десктоп. Подробнее — `project_description.md`, раздел 3.

## 3. Модель данных

Все суммы — целые копейки (`Kopecks`, в Postgres `bigint`). Идентификаторы — UUID. Даты расходов — `date` без времени (`YYYY-MM-DD`); метки времени — `timestamptz`, в JSON — ISO 8601 UTC. В TypeScript поля в camelCase, в Postgres — snake_case (`amount_kop`, `payer_id`), преобразование — в слое API.

| Таблица Postgres | Поле → тип → ограничение |
|---|---|
| `profiles` | `id uuid PK = auth.users.id`; `email text`; `name text CHECK (char_length BETWEEN 1 AND 40)`; `created_at timestamptz DEFAULT now()` |
| `groups` | `id uuid PK`; `name text CHECK (1–50 символов)`; `emoji text NOT NULL DEFAULT '💸'`; `owner_id uuid → profiles`; `invite_token text UNIQUE`; `hidden_at timestamptz NULL`; `created_at` |
| `members` | `group_id → groups`, `user_id → profiles`, PK (`group_id`, `user_id`); `joined_at timestamptz`; `left_at timestamptz NULL` |
| `expenses` | `id uuid PK`; `group_id`; `title text CHECK (1–60)`; `amount_kop bigint CHECK (amount_kop BETWEEN 1 AND 100000000)`; `payer_id`; `split jsonb`; `category text NULL` (зарезервировано); `date date`; `created_by`; `created_at`; `updated_at`; индекс (`group_id`, `date DESC`, `created_at DESC`) |
| `transfers` | `id uuid PK`; `group_id`; `from_id`; `to_id`; `amount_kop bigint CHECK (> 0)`; `created_by`; `created_at`; `CHECK (from_id <> to_id)`; индекс (`group_id`, `created_at DESC`) |

`split` (тип `ExpenseSplit`): `{ kind: 'equal', memberIds: string[] }` | `{ kind: 'shares', shares: { memberId: string, weight: 1…1000 }[] }`; список не пустой, без повторов, только участники группы.

**Инварианты:** сумма долей расхода = `amountKop`; сумма балансов группы = 0; `fromId ≠ toId`; активных участников (`left_at IS NULL`) не больше 50.

### 3.1. Доступ (RLS) и серверные функции

| Таблица | SELECT | INSERT | UPDATE / DELETE |
|---|---|---|---|
| `profiles` | свой профиль и профили участников общих групп | только свой (при регистрации) | только свой |
| `groups` | участники группы (в т. ч. вышедшие — для истории) | любой вошедший, `owner_id = auth.uid()` | `invite_token` — только владелец (перевыпуск); удаление запрещено |
| `members` | участники группы | только через RPC `join_group` | только своя строка `left_at` через RPC `leave_group` |
| `expenses` | участники группы | активный участник, `created_by = auth.uid()` | только `created_by = auth.uid()` и если среди участников нет вышедших |
| `transfers` | участники группы | активный участник, `auth.uid() IN (from_id, to_id)` | DELETE — только `created_by = auth.uid()`; UPDATE запрещён |

RPC с `security definer` (обходят RLS, сами проверяют права):
- `get_invite_preview(token) → { groupName, emoji, membersCount }` — доступна гостю; для неверного токена — ошибка `invalid_invite`;
- `join_group(token)` — добавляет вызывающего в `members` или обнуляет его `left_at`; ошибки `invalid_invite`, `group_full`;
- `leave_group(group_id)` — проверяет нулевой баланс (иначе `balance_not_zero` с суммой), ставит `left_at`, передаёт `owner_id` (Q4);
- `rotate_invite(group_id)` — только владелец, новый `invite_token`.

## 4. Функциональные требования

### F-1. Аутентификация (US-01)
- **FR-1.1** Регистрация по email, имени (1–40 символов) и паролю (не короче 8 символов); подтверждение email отключено, после регистрации пользователь сразу попадает на `/` (AC-01.1, 01.2, AC-T1.1). Вход по email и паролю; выход из аккаунта в меню профиля (AC-T1.2).
- **FR-1.2** Все маршруты, кроме `/login`, `/register`, `/join/:token`, требуют входа; неавторизованный пользователь перенаправляется на `/login?next=<исходный адрес>` и после входа возвращается туда (AC-T1.3).
- **FR-1.3** Ошибка входа не раскрывает, что именно неверно (AC-01.3).

### F-2. Группы и участники (US-02, 03, 11)
- **FR-2.1** Список групп пользователя (без групп, из которых он вышел, и скрытых): эмодзи, название, число активных участников, баланс пользователя в группе в формате FR-4.2; сортировка — по времени последней операции (AC-T2.1).
- **FR-2.2** Создание группы: название 1–50 символов, эмодзи из 8 вариантов (по умолчанию 💸); создатель становится участником и владельцем (AC-02.1, 02.2).
- **FR-2.3** Приглашение: любой участник нажимает «Пригласить» → ссылка `/join/:inviteToken` копируется в буфер (AC-03.1). Экран `/join/:token` показывает превью через `get_invite_preview`; «Вступить» вызывает `join_group` (AC-03.2, 03.3); неверный токен — AC-03.4; группа полна — «В группе уже 50 участников».
- **FR-2.4** Выход из группы через `leave_group` только при нулевом балансе (AC-11.1, 11.2); вышедший остаётся в истории с пометкой «не в группе» (нейтрально по роду; уточнено в ДЗ4), не доступен для выбора в новых расходах и может вернуться по действующей ссылке (Q5). Правила для владельца — Q4.
- **FR-2.5** Владелец может перевыпустить ссылку («Сбросить ссылку» с подтверждением); старая ссылка сразу даёт AC-03.4 (AC-T2.2).
- **FR-2.6** Список участников: на вкладке «Балансы» показаны все активные участники с аватаром-инициалом, даже с нулевым балансом.

### F-3. Расходы (US-04, 05, 09)
- **FR-3.1** Лента расходов: сортировка по Q12; строка — название, сумма, плательщик («Вы заплатили» для себя), «на N человек» или «по долям A 2 : B 1», «Ваша доля X» (если пользователь не участвует — «Вас не касается») (AC-T3.1).
- **FR-3.2** Форма расхода. Обязательные поля — **название и сумма**; остальные заполнены по умолчанию: плательщик — текущий пользователь, участники деления — все активные, режим — «поровну», дата — сегодня (AC-04.1). Для чужого расхода маршрут `/expenses/:expenseId` открывает режим просмотра без полей ввода.
- **FR-3.3** Ввод суммы — разбор строки без float (функция `parseRubToKop`), правила:

  | Ввод | Результат |
  |---|---|
  | `12000`, `12 000`, `12000,5`, `12000.50`, `0,01` | 1 200 000 / 1 200 000 / 1 200 050 / 1 200 050 / 1 коп. |
  | пробелы по краям | обрезаются |
  | `0`, `-5`, `+5`, `12,345`, `12,`, `,5`, `1e3`, `12.000,00`, пусто | ошибка «Введите сумму больше 0, до копеек» |
  | больше 1 000 000 ₽ | ошибка «Сумма не больше 1 000 000 ₽» |

  Регулярное выражение для допустимого ввода: `^\d{1,3}( ?\d{3})*([.,]\d{1,2})?$` или `^\d+([.,]\d{1,2})?$`; ведущие нули допускаются (`007` = 7 ₽) (AC-04.3, AC-T3.2).
- **FR-3.4** Деление — функция `splitByWeights(amountKop, weights)`: база `q = Math.floor(amount * w / Σw)` (разрешено: все значения — целые меньше 2⁵³), остаток раздаётся по копейке методом наибольших остатков, при равенстве остатков — по порядку участника в группе (Q1). В режиме «поровну» все веса равны 1 (AC-04.2, 05.1, 05.2, AC-T3.3).
- **FR-3.5** Изменять и удалять расход может только его автор и только если среди участников расхода нет вышедших (Q5); у остальных кнопки **скрыты** (AC-09.1, 09.3). Удаление: диалог подтверждения → запрос `DELETE` отправляется **через 5 секунд**; в это время расход скрыт из ленты, а тост предлагает «Отменить» (отмена — запрос не отправляется). Если вкладку закрыли раньше, запрос отправляется в `beforeunload`/`visibilitychange` через `navigator.sendBeacon`, иначе расход остаётся (AC-09.2, AC-T3.4).

### F-4. Балансы и «Кто кому должен» (US-06, 07)
- **FR-4.1** Баланс участника = Σ оплаченного − Σ своих долей + Σ отправленных переводов − Σ полученных переводов.
- **FR-4.2** Тексты и цвета балансов (знак долга всегда передан текстом, не только цветом):

  | Чей баланс | > 0 | < 0 | = 0 |
  |---|---|---|---|
  | свой (шапка, список групп) | «Вам должны 8 135,80 ₽» | «Вы должны 940,75 ₽» | «Вы в расчёте» |
  | чужой (вкладка «Балансы») | «Ане должны 8 135,80 ₽» | «У Бори долг 940,75 ₽» (не зависит от пола участника) | «Вика в расчёте» |
  | цвет | `text-emerald-700` | `text-rose-600` | `text-slate-500` |

  Контраст всех трёх цветов на белом — не ниже 4,5:1 (NFR-2) (AC-06.1, AC-T4.1).
- **FR-4.3** Список переводов — детерминированный алгоритм: (1) сначала закрываются пары должник–кредитор с точно совпадающими суммами; (2) затем жадно: крупнейший должник → крупнейшему кредитору. Сортировка во всех шагах — по сумме по убыванию, при равенстве — по порядку участника в группе (Q1). N — число участников с ненулевым балансом; переводов не больше N−1 (AC-07.1, 07.2, AC-T4.2).
- **FR-4.4** Расчёт — чистые функции в `src/features/balances/`. **Эталон** — TypeScript-модуль из ДЗ2 (`experiments/results/cot_step3.md`, `cot_step4.md`) с правилом сортировки из FR-4.3; `settle.js` из ДЗ1 использовался только для сверки чисел в AC. Контрольный пример — AC-07.1.
- **FR-4.5** Шапка группы (концепция 1): эмодзи и название, аватары участников, крупно свой баланс в формате FR-4.2 и кнопка «Рассчитаться» по правилу Q3 (AC-T4.3).
- **FR-4.6** Вкладка «Балансы»: список участников с балансами и полосками (зелёные — им должны, красные — они должны, длина пропорциональна модулю баланса), ниже блок «Кто кому должен» со стрелками; строки текущего пользователя подсвечены (концепция 2). На десктопе — правая панель с «Итого расходов» (концепция 3).

### F-5. Переводы и история (US-08, 10)
- **FR-5.1** Кнопка «Отметить перевод» есть только у отправителя и получателя перевода. Диалог: сумма по умолчанию из подсказки, можно уменьшить (от 0,01 ₽, правила FR-3.3); после подтверждения и ответа сервера создаётся `Transfer`, балансы пересчитываются (AC-08.1, 08.2, AC-T5.1). Автор может удалить ошибочный перевод с подтверждением (без отложенной отмены).
- **FR-5.2** История: расходы и переводы одной лентой, сортировка по Q12 (для перевода `date` = дата `createdAt`), у каждой записи — автор и сумма; вышедшие участники — с пометкой «не в группе» (AC-10.1).

## 6. Обработка ошибок

**Валидация** выполняется при потере фокуса полем и при отправке. Кнопка отправки всегда активна (так доступнее для клавиатуры и скринридеров); при нажатии с ошибками запрос не отправляется, ошибки показываются под полями, фокус переходит на первое ошибочное поле, введённые данные сохраняются.

| ID | Ошибка | Где | Поведение и текст |
|---|---|---|---|
| ERR-1 | Невалидная сумма, название, доли, пустой список участников | формы расхода, группы, перевода | правило выше; тексты: «Введите название», «Введите сумму больше 0, до копеек», «Сумма не больше 1 000 000 ₽», «Доля — целое число от 1 до 1000», «Выберите хотя бы одного участника» (AC-02.2, 04.3, 04.4, 05.3) |
| ERR-2 | Нет групп / нет расходов / все в расчёте | списки | empty-состояние: «Создайте первую группу или попросите ссылку у друзей» + «Создать группу»; «Пока все в расчёте. Добавьте первый расход» + «Добавить расход»; «Все в расчёте 🎉» (AC-06.3, 07.3) |
| ERR-3 | Сетевая ошибка при загрузке | экраны | скелетон → «Не удалось загрузить данные» + «Повторить» (AC-T9.1) |
| ERR-4 | Сетевая ошибка при сохранении | формы, «Отметить перевод» | для расхода — оптимистичная строка удаляется из ленты, форма открывается снова с введёнными данными; для перевода — диалог не закрывается; тост «Не удалось сохранить. Проверьте интернет» + «Повторить»; балансы не меняются (AC-08.3, AC-T6.1) |
| ERR-5 | 500 и неожиданные ошибки | все | «Что-то пошло не так. Мы уже разбираемся» + «Повторить»; детали — только в консоль разработчика (AC-T6.2) |
| ERR-6 | 401 — сессия истекла | все | переход на `/login?next=…` с сообщением «Сессия истекла, войдите снова», после входа — возврат (AC-T6.3) |
| ERR-7 | 403/404 — нет доступа к группе или расходу | группа, расход | группа: «Группа недоступна — возможно, вы вышли из неё или ссылка устарела» + «К моим группам»; чужой расход — кнопки скрыты, при прямом запросе — тост «Изменять можно только свои расходы» (AC-09.3, AC-T6.4) |
| ERR-8 | Недействительное приглашение | `/join/:token` | «Приглашение недействительно. Попросите новую ссылку» + «К моим группам» (AC-03.4) |
| ERR-9 | Выход с ненулевым балансом | группа | «Сначала рассчитайтесь: вы должны 940,75 ₽» (или «вам должны …»), выход не выполняется (AC-11.2) |
| ERR-10 | Конфликт: расход уже удалён (например, с другого устройства автора) | форма расхода | «Этот расход уже удалён» + закрытие формы и обновление ленты (AC-T6.5) |
| ERR-11 | Долгий ответ сервера (> 10 с) | все кнопки отправки | индикатор на кнопке, повторное нажатие заблокировано с первого клика; через 10 с — тост «Сервер отвечает дольше обычного». Кнопки «Повторить» в нём нет: запрос ещё идёт, и повтор создал бы дубль; если ответ придёт с ошибкой, сработает ERR-4 (AC-T6.6, уточнено в ДЗ4) |
| ERR-12 | Группа заполнена | `/join/:token` | «В группе уже 50 участников» + «К моим группам» |
| ERR-13 | Изменение расхода с вышедшим участником | форма расхода | кнопки «Изменить»/«Удалить» скрыты, подсказка «В расходе есть вышедший участник — изменить его нельзя» |

## 9. Дополнительные критерии приёмки (AC-T)

Дополняют `user_stories.md` для требований, у которых там не было критериев.

- **AC-T1.1** Given гость вводит имя длиннее 40 символов или пароль из 7 символов, When нажимает «Создать аккаунт», Then аккаунт не создаётся, а под полем показывается «Имя — от 1 до 40 символов» или «Пароль — не короче 8 символов».
- **AC-T1.2** Given вошедший пользователь, When выбирает «Выйти» в меню профиля, Then сессия завершается и открывается `/login`.
- **AC-T1.3** Given гость открывает `/groups/42`, When входит, Then попадает на `/groups/42`, а не на `/`.
- **AC-T2.1** Given у Бори группы «Поездка в Казань» (баланс −940,75 ₽) и «Квартира» (0 ₽), When он открывает `/`, Then видит обе группы с текстами «Вы должны 940,75 ₽» и «Вы в расчёте».
- **AC-T2.2** Given владелец сбросил ссылку, When кто-то открывает старую ссылку, Then показывается «Приглашение недействительно. Попросите новую ссылку».
- **AC-T3.1** Given расход «Кофе 600 ₽, по долям Гоша 2 : Боря 1», When его видит Аня, Then в строке написано «по долям Гоша 2 : Боря 1» и «Вас не касается».
- **AC-T3.2** Given поле суммы, When пользователь вводит «12 000,5», Then сохраняется 1 200 050 коп.; When вводит «12,», Then показывается «Введите сумму больше 0, до копеек».
- **AC-T3.3** Given участники вступили в порядке Аня, Боря, Вика, When расход 1 000 ₽ делится поровну, Then 333,34 ₽ достаётся Ане.
- **AC-T3.4** Given автор удалил расход, When в течение 5 секунд нажимает «Отменить», Then расход возвращается в ленту, а запрос на удаление не отправляется.
- **AC-T4.1** Given балансы Аня +8 135,80, Боря −940,75, When Боря открывает «Балансы», Then видит «Ане должны 8 135,80 ₽» и в своей строке «Вы должны 940,75 ₽».
- **AC-T4.2** Given балансы А −100, Б −100, В +100, Г +100 ₽, When рассчитан список, Then переводы «А → В 100,00 ₽» и «Б → Г 100,00 ₽» (порядок вступления А, Б, В, Г), и результат одинаков при каждом запуске.
- **AC-T4.3** Given у Бори один предложенный перевод «Боря → Аня 940,75 ₽», When он нажимает «Рассчитаться», Then открывается диалог «Отметить перевод» с этим переводом; Given у Ани баланс > 0, Then кнопки «Рассчитаться» у неё нет.
- **AC-T5.1** Given перевод «Боря → Аня 940,75 ₽», When Боря меняет сумму на 500 и подтверждает, Then баланс Бори становится −440,75 ₽, а в списке остаётся «Боря → Аня 440,75 ₽».
- **AC-T6.1** Given нет сети, When пользователь сохраняет новый расход, Then расход сначала появляется в ленте, затем исчезает, форма открывается с введёнными данными, и показывается тост с «Повторить».
- **AC-T6.2** Given сервер ответил 500, When загружается группа, Then показывается «Что-то пошло не так. Мы уже разбираемся» и «Повторить», а текст ошибки сервера на экран не выводится.
- **AC-T6.3** Given сессия истекла, When пользователь нажимает «Сохранить», Then открывается `/login` с «Сессия истекла, войдите снова», после входа — возврат на исходный экран.
- **AC-T6.4** Given пользователь не участник группы, When открывает `/groups/:id`, Then видит «Группа недоступна…» и кнопку «К моим группам».
- **AC-T6.5** Given расход удалён с другого устройства, When автор сохраняет его в открытой форме, Then показывается «Этот расход уже удалён», форма закрывается, лента обновляется.
- **AC-T6.6** Given сервер не ответил за 10 с, When пользователь ждёт после «Сохранить», Then кнопка показывает индикатор и не реагирует на повторные нажатия, а затем появляется тост «Сервер отвечает дольше обычного».
- **AC-T9.1** Given загрузка экрана «Группа» не удалась, When экран открыт, Then вместо скелетона показывается «Не удалось загрузить данные» и «Повторить», а нажатие «Повторить» снова запускает загрузку.
